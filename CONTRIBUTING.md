# Участие в проекте

Спасибо, что помогаете. Проект неофициальный и не связан с Мутагеном (mutagen.ru). Issue и pull request можно писать по-русски или по-английски. Issues and pull requests in English are welcome too.

## Никогда не публикуйте ключ API

Ключ Мутагена стоит прямо в адресе запроса, поэтому легко попадает в логи. Перед тем как вставить вывод в issue или PR, проверьте, что ключа там нет: наш код заменяет его на `***`, но сторонние инструменты (curl, прокси, отладчик) этого не делают. Если ключ все-таки утек, перевыпустите его в кабинете, см. [SECURITY.md](SECURITY.md).

## Как запустить

Нужен Node.js 22.12 или новее.

```bash
git clone https://github.com/SVorobiev-ru/mutagen-ru-mcp.git
cd mutagen-ru-mcp
npm ci
npm run build
```

Ключ для ручной проверки кладите в `.env` (он в `.gitignore`), образец — `.env.example`:

```bash
cp .env.example .env   # впишите MUTAGEN_API_KEY
set -a; . ./.env; set +a
node dist/cli/bin.js balance
```

## Проверки

| Команда | Что делает |
|---|---|
| `npm run check` | Все сразу: lint, typecheck, тесты, сборка. Должна быть зеленой перед PR |
| `npm run lint` | Biome: линтер и форматирование. Исправить формат: `npm run format` |
| `npm run typecheck` | TypeScript в строгом режиме |
| `npm test` | Модульные и контрактные тесты (vitest) |
| `npm run test:coverage` | Тесты с покрытием и порогами по папкам |
| `MUTAGEN_LIVE=1 npm run test:live` | Живые тесты на реальном API со своим ключом, не дороже 2 ₽ за прогон; без `MUTAGEN_LIVE=1` пропускаются |
| `npm run smoke:mcp` | Список инструментов MCP через MCP Inspector (после `npm run build`) |
| `npm run smoke:cli` | Версия и справка CLI |

CI запускает `npm run check`, `npm run smoke:mcp` и `npm pack --dry-run` на Node 22 и 24 (Ubuntu) и Node 22 (Windows).

## Тесты

- `test/unit` — модульные тесты. HTTP заменен заглушкой `fetch`, ключ и деньги не нужны.
- `test/contract` — контрактные тесты на настоящих ответах API из `test/fixtures/live`. Ответы записаны вживую, из них убраны ключ и личные данные аккаунта: названия заданий, фразы клиентов, баланс.
- `test/live` — живые тесты на реальном API: баланс, формат ошибки (неизвестный метод → 108), `serp.report` (111 без подписки), `parser.get` на одной фразе, массовое задание на двух фразах и его поиск в списке заданий, «Ключи Вордстата» на 200 фраз. Конкуренцию и ставки Директа набор не трогает: они зависят от Директа и могут считаться часами. Запуск вручную, около 0,10 ₽:

  ```bash
  MUTAGEN_API_KEY=ваш_ключ MUTAGEN_LIVE=1 npm run test:live
  ```

  Набор работает с временными каталогами кэша и журнала, бюджет прогона жестко ограничен 2 ₽ через `MUTAGEN_BUDGET_RUB`, а в конце сверяет баланс до и после: разница больше 2 ₽ роняет прогон. В `npm test` и CI живые тесты не входят: они тратят деньги.
- Если проверяете изменение на реальном API вручную, ставьте маленький предел: `MUTAGEN_BUDGET_RUB=1`, и сначала смотрите смету через `--dry-run`. Отчеты Мега-инструмента без подписки вживую не проверить: они покрыты модульными тестами на заглушках по документации API.

Новая фикстура — это ответ API, сохраненный в `test/fixtures/live` без ключа и личных данных, плюс тест в `test/contract`.

## Новый метод API или отчет

1. Откройте issue по шаблону «Новый метод API»: ссылка на документацию Мутагена, параметры, пример ответа без личных данных, цена.
2. Метод — в `src/core/client.ts` и `src/core/types.ts`, цена — в `src/budget/pricing.ts`, отчет Мега-инструмента — в `src/core/reports.ts`.
3. Платный метод обязательно проходит через смету и `SpendGuard`: вызов без сметы не примем.
4. Если метод нужен агенту, добавьте инструмент в `src/mcp/tools/` и команду в `src/cli/commands/`, цену — в описание инструмента, строку — в таблицу инструментов в README.md и README.en.md.

## Стиль

- TypeScript в строгом режиме, ESM, форматирование и линтер — Biome.
- Новая зависимость — только с обоснованием в PR. Сейчас в рантайме их пять.
- Тексты для пользователя — на русском и английском, как в существующих сообщениях.
- Скрейпинг сайта Мутагена не принимаем: только официальный API и локальная обработка.

## Коммиты и PR

Сообщения коммитов — в стиле [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/):

```text
feat(cli): флаг --region для команды plan
fix(core): повтор на ошибке 110
docs(readme): пример для Windsurf
test(contract): фикстура parser.mass.id без региона
```

Типы: `feat`, `fix`, `docs`, `test`, `refactor`, `perf`, `chore`, `ci`, `build`. Ломающее изменение — `!` после типа и раздел `BREAKING CHANGE:` в теле. По типам коммитов собирается [CHANGELOG.md](CHANGELOG.md).

Перед PR:

- `npm run check` проходит;
- новое поведение покрыто тестами;
- README.md и README.en.md обновлены, если изменились инструменты, команды, цены или настройки;
- в коде, тестах и описании PR нет ключа API и личных данных.
